# OpsLion · 运营狮

仓库分为三个部分

- **浏览器插件** — 从秀米获取模板，将排好的文章导回秀米
- **Skills** — 将材料和模板交给网页端大模型，生成排版文件
- **排版台** — 在本地导入材料、选择模板、排版和修改，可选用 AI 增强

按需要选择使用方式

- **在网页端使用大模型** — 安装插件 → 下载秀米模板 → 将 Skill、模板和材料一起上传到网页对话 → 用插件导入成稿
- **在本地使用排版台** — 安装插件和排版台 → 导入材料和模板 → 一键排版 → 修改内容 → 用插件导入成稿

---

## 浏览器插件

Xiumi Bridge 安装在 Chrome 或 Edge 中，负责获取模板和导入成稿

### 安装插件

- **找到插件位置**
  - 插件在 `public\downloads\xiumi-bridge-extension`
- **打开浏览器扩展管理页**
  - Chrome 在地址栏输入 `chrome://extensions/`
  - Edge 在地址栏输入 `edge://extensions/`
  - 开启页面中的 **开发者模式** 或 **开发人员模式**
- **加载插件**
  - 点击 **加载已解压的扩展程序** 或 **加载解压缩的扩展**
  - 选择上述文件夹
  - 安装后，将 **运营狮 · Xiumi Bridge** 固定到浏览器工具栏
  - 刷新已经打开的秀米页面

### 获取秀米模板

- 在秀米打开要沿用的文章，进入编辑页，等待正文和图片加载完成
- 打开浏览器工具栏中的 Xiumi Bridge
- 点击 **抓取当前页面排版**
- 抓取完成后，按使用方式选择
  - **网页端使用 Skills** — 点击 **下载模板包**，保存 `*.opslion-template.json`
  - **本地使用排版台** — 排版台启动后点击 **发送到 OpsLion**，或下载模板包后手动导入

模板包可以直接用于排版，模板结构由 Skill 或排版台解析

### 将成稿导入秀米

- **取得排版文件**
  - 网页模型返回的文件为 `article.xiumi.json`
  - 排版台通过 **导出 → 下载 Bridge 数据包** 生成 `*.xiumi.json`

- **打开秀米编辑页**
  - 登录秀米，新建一篇空白图文
  - 在这篇空白图文中打开 Xiumi Bridge

- **导入文件**
  - 点击 **选择 Bridge 数据包**，选择 `.xiumi.json` 文件
  - 点击 **分模块导入空白图文**
  - 等待图片上传和模块写入完成，期间保持编辑页打开

- **保存文章**
  - 导入完成后，在秀米保存文章
  - 重新打开文章，点击插件中的 **检查保存后重开的稿件**
  - 后续可以继续在秀米修改文字、图片和版式

### 插件使用中的问题

- **加载时找不到 `manifest.json`**
  - 检查是否已经选择直接包含 `manifest.json` 的文件夹
- **抓取成功，但发送到 OpsLion 失败**
  - 启动本地排版台后重试
  - 也可以点击 **下载模板包**，在排版台中手动读取
  - 网页端使用 Skills 时，使用下载的模板包
- **图片上传或导入失败**
  - 根据插件提示检查登录状态和失败的素材
  - 确认选择的是 `.xiumi.json` 成稿文件，并在空白图文中执行分模块导入

## Skills

Skills 直接在网页端大模型对话中使用，模型读取说明并运行随附脚本，完成模板解析和排版

本机只需安装浏览器插件，下面以秀米排版 Skill 为例说明用法

### 准备使用环境

- 使用能够上传附件、解压文件并运行 Python 的网页模型对话（如 GPT）
- 用于自动化排版的 skill 是 `skills\Xiumi_Layout_Skill.zip`

### 上传文件

在同一个对话中上传三类文件

- **完整 Skill 包**
  - 上传整个 ZIP，供模型解压后读取和执行

- **原始秀米模板**
  - 上传插件通过 **下载模板包** 导出的 `*.opslion-template.json`
  - 多个模板同时上传时，在消息中说明本次使用哪一个

- **本期原始材料**
  - 文案使用 `.docx`，文案和图片放在一起时可以上传材料 ZIP
  - 照片、海报、二维码等未包含在 Word 或 ZIP 中时，另外上传
  - 图片已经包含在材料中时，上传一份即可
  - 有多份 Word 时，说明哪份是主稿、哪份是参考材料
  - 配图顺序、沿用旧图等要求直接写在消息里

文案和配图已经放在一个 ZIP 中时，只需上传 Skill ZIP、模板 JSON、材料 ZIP

### 开始排版

上传完成后发送以下指令，可在末尾补充本次要求

```text
请解压 Skill 包，完整读取其中的 SKILL.md，并实际运行随附脚本

根据我上传的原始材料和秀米模板完成排版
先解析原始模板，再沿用其中的结构、样式和装饰放入本期内容
保留文案、链接和配图对应关系，检查实际效果并修正发现的问题

完成后提供可由浏览器插件导入秀米的 article.xiumi.json
同时提供预览文件和后续修改用的 work.zip
```

模型提出缺图或主稿冲突时，在原对话中补充对应文件或说明，再继续生成

### 取得结果

- **`article.xiumi.json`**
  - 用 Xiumi Bridge 的 **选择 Bridge 数据包** 打开
  - 按前文的 **将成稿导入秀米** 操作完成导入

- **`preview.html` 和 `review.html`**
  - 在浏览器中打开，查看排版效果、内容对应关系和检查记录

- **`work.zip`**
  - 保存本次模板、材料提取结果和排版记录，用于后续修改
  - 原始 Word、材料 ZIP 和图片另行保留

### 修改已经排好的文章

- 在原对话中说明要修改的位置和内容，例如修改报名日期、删除某段或更换第二张图片
- 有新材料时一并上传，要求基于上一版修改并重新输出排版文件
- 另开对话时，上传完整 Skill 包、上一版 `work.zip` 和本次新增材料
- 修改完成后，下载新版 `article.xiumi.json` 和 `work.zip`

## 排版台

排版台在本地运行，可导入材料和新模板、执行一键排版，也可手工增删改内容

普通文章使用 **本地排版** 即可完成导入、排版和导出，模型在 **AI 增强** 中单独配置

### 安装与启动

- **准备运行环境**
  - 使用 Windows，浏览器使用 Chrome 或 Edge
  - 安装 [Node.js](https://nodejs.org/en/download)，版本为 **22.13.0 或更高**
  - 安装 [Python](https://www.python.org/downloads/windows/)，版本为 **3.10 或更高**
  - 安装 Python 时勾选 `Add python.exe to PATH`

- **检查安装结果**
  - 在开始菜单搜索并打开 PowerShell
  - 依次运行以下命令，确认都能显示版本号

    ```powershell
    node --version
    npm.cmd --version
    python --version
    ```

  - 安装完成后仍提示找不到命令时，关闭并重新打开 PowerShell 后再试

- **下载并解压排版台**
  - 从仓库下载排版台，也可以在仓库首页点击 **Code → Download ZIP** 下载完整仓库
  - 将文件完整解压到固定目录
  
- **启动排版台**
  - 双击 `启动排版台.bat`
  - 首次启动需要联网安装依赖，等待命令窗口完成后会打开浏览器
  - 浏览器没有自动打开时，访问 `http://127.0.0.1:3000`

- **结束使用**
  - 双击 `关闭排版台.bat` 停止本地服务
  - 下次使用时重新运行启动脚本

#### 启动失败时

- 打开排版台目录，在文件资源管理器地址栏输入 `powershell` 并回车
- 在打开的窗口中运行以下命令，查看完整报错

  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
  ```

- 提示找不到 Node.js、npm 或 Python 时，重新检查安装结果
- 提示服务已经运行时，先访问 `http://127.0.0.1:3000`
- 需要重启时，先运行关闭脚本，再运行启动脚本
- 日志位于排版台目录中的 `.local-studio.log` 和 `.local-studio-error.log`

### 使用文章模板排版

- **选择模板**
  - 进入 **快速排版 → 模板库**
  - 选择模板并查看预览，点击 **套用到当前文章**

- **导入 Word**
  - 点击 **导入 Word**，选择 `.docx` 文件
  - 在导入页查看文字、链接和图片，按提示处理表格或复杂编号
  - 新稿选择 **新建文章，使用当前模板**，然后点击 **确认导入**
  - 更新已有文章时，可以选择 **替换当前文章**，或选中画布内容后仅替换选中部分

- **执行排版**
  - 选择 **本地排版**，点击 **一键排版**
  - 在中间预览区查看结果
  - 根据提示补齐图片，处理未排入的内容，再进行局部修改或导出

### 导入 Word、图片和 ZIP

材料分散在多个文件中时，使用顶部的 **交稿** 入口

- 先选模板，再打开 **交稿**，核对面板中显示的模板名称
- 点击 **添加 Word、图片或 ZIP**，选择本期材料
  - 可以一次添加多份文件
  - 图片已嵌入 Word 或放进 ZIP 时，上传一份即可
  - 多份文案同时导入时，指定本次主稿
- 点击交稿面板中的 **一键排版**
- 在 **文章配图与来源** 中检查图片位置和素材，配错时直接更换
- 后补的二维码或照片从交稿面板追加，传错文件时使用 **替换文件、停用、启用、移除**

### 沿用秀米模板

- **读取模板**
  - 排版台启动后，在插件中抓取原稿并点击 **发送到 OpsLion**
  - 已有模板文件时，进入 **样式复刻 → 从文件读取**，打开 `*.opslion-template.json`
  - 点击 **分析结构和替换位**，查看模板预览

- **保存原模板**
  - 点击 **保存为模板**
  - 以后从 **历史模板库** 载入，再替换本期内容

- **放入新材料**
  - 单份 Word 使用 **导入新版 DOCX**，导入后点击 **本地一键套版**
  - Word、图片或 ZIP 一起提供时，使用顶部 **交稿**，再执行 **一键排版**

- **调整内容与模块**
  - 在 **逐项替换** 中修改文字、链接和图片
  - 在 **模块结构** 中复制或隐藏原模板模块
  - 新稿超出原模板容量时，在 **未排入内容** 中复制合适的原模块或追加正文模块

历史模板的本地套版适合结构相近的稿件，内容差异较大时需要调整模块和文字对应关系

### 手工修改

- **文字和内容顺序**
  - 文章模板在左侧编辑区修改文字、增加或删除内容、调整顺序
  - 历史模板使用 **逐项替换** 和 **模块结构**

- **图片和局部版式**
  - 在图片项或 **文章配图与来源** 中换图
  - 选中段落或图片，在右侧选择模板提供的组件样式和单图、双图、三图组合

- **恢复修改**
  - 使用编辑区的撤销操作
  - 替换 Word、模型应用和批量排版前保留的版本，可从 **项目** 中打开

### 导出与备份

- **导入秀米**
  - 点击 **导出 → 下载 Bridge 数据包**，保存 `*.xiumi.json`
  - 按前文插件部分的步骤导入秀米
  - 导出面板推荐 **复制富文本** 时，也可以复制后粘贴到秀米
  - 含本地或 Word 内嵌图片的文章使用 Bridge，由插件上传图片

- **处理导出提示**
  - 必需正文未排入、配图未补齐或要求未处理时，先处理对应事项
  - 材料尚未齐全时，可以先保存项目备份和 HTML 预览，之后继续编辑

- **保存项目**
  - 项目自动保存在当前浏览器中
  - 下次使用同一浏览器打开同一地址，从 **项目** 继续编辑
  - 点击 **项目 → 备份当前项目**，下载 `*.layout.json`
  - 恢复备份或换电脑时，点击 **项目 → 导入项目**
  - 清理浏览器数据前先备份，原始 Word 和图片另行保留

### AI 增强

- 打开 **模型设置**，填写兼容 OpenAI 接口的 API 地址、模型名称和 API Key
- 点击 **保存并测试**
- 回到排版台，选择 **AI 增强**，再点击 **一键排版**
- 历史模板使用左侧的 **Agent 智能套版**，查看修改对照后应用

任务所需的文字和模板信息会发送到配置的模型服务，调用费用由该服务收取

网页端 Skills 使用网页对话中的模型，排版台的 AI 增强使用这里配置的 API

### 周报

- 周报采集需要接入公众号 RSS
- 进入 **周报**，选择日期后采集推文，或导出已有推文 ZIP
- 处理后的 `.md`、`.txt` 文案通过 **导入处理好的文案** 保存和预览
- 当前这条文案导入流程暂不支持成品 HTML 或 Bridge 导出

## 后记

作为第一个版本，它应该算是赶工出来的，我因为懒也没有做过多的测试（其实是还没实战用过），其实就算是现在我也还有一些改进的想法，但是我暂时不想再动了（

原本还可以找借口说是因为额度用完了，谁知道就在今天 Tibo 重置了，这下只能说纯粹是因为我懒了（

在做到一半的时候，我突然意识到其实对于有 GPT 订阅的人来说，直接用网页端可能会比接各种 api 的效果还要好，agent 还真未必有 skill 好用，所以我也提供了排版的 skill，可以在 GPT 网页端里新建一个项目，把我们 skill 的压缩包作为来源加进去，这样每次要用的时候就可以新开一个对话，只发材料和浏览器插件导出的模板即可

一开始觉得这个项目应该并不困难，但是实际做了之后才感觉到也还是有一些值得思考的问题，而且我严重怀疑我的一些想法曾将 GPT 大人引向了不那么好的方向。唉不知道我的神秘想法给 GPT 大人带来了多大的限制与误导，AI 大人何时逃离原生用户？

总之先草草地发上了这个第一版，肯定还有很多问题，留待未来的我和 AI 解决
