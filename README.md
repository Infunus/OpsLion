# OpsLion

一个浏览器插件，配合两个排版 Skill：采集公众号资料，将资料和文案交给 AI 生成秀米原生成稿，再用同一个插件导入秀米。

## 发布内容

| 文件 | 用途 |
| --- | --- |
| `plugin/` | 运营狮统一插件 0.9.0，包含秀米抓取/导入和公众号采集台 |
| `skills/Xiumi_Native_Layout_Skill_v2.4.5.zip` | 按已有秀米模板排版，支持排版微调、原生表格操作与文案审核 |
| `skills/OpsLion_Hello_Week_Skill_v4.0.1.zip` | Hello Week 采编、原生模板、素材和生成器一体包 |
| `skills/xiumi-native-layout/`、`skills/opslion-hello-week/` | 两个 Skill 的可读源文件，与对应 ZIP 一致 |
| `LICENSE` | 项目许可证；第三方代码保留各自许可证 |

## 安装插件

1. 解压发布包，保留 `plugin` 目录内全部文件。
2. Edge 打开 `edge://extensions/`，Chrome 打开 `chrome://extensions/`，开启开发者模式。
3. 点击“加载解压缩的扩展”，选择直接包含 `manifest.json` 的 `plugin` 目录。
4. 固定工具栏中的“运营狮”。弹窗提供 **抓取排版、导入排版、公众号采集** 三个入口。

需要 Chrome / Edge 116 或以上版本。浏览器插件无需 Node.js、Python 或本地 BAT 服务；登录和验证使用安装插件的当前浏览器。

保留已有缓存升级时，先备份原插件目录和已导出的资料，将新版文件覆盖到原来的加载目录，在扩展管理页点击重新加载，并重新打开采集台。保持相同浏览器配置和加载路径，不要卸载扩展。换路径或卸载可能导致本地存储隔离或删除。

统一插件整合原生排版核心与修复原文链接后的采集模块，只需安装一次。已有独立采集或旧排版插件可在升级后停用，避免点击混淆。

## 公众号采集

1. 点击插件 **打开公众号采集台**，再点 **微信扫码登录**。二维码不能直接显示时会打开微信读书登录页。
2. 粘贴公众号的一篇文章链接，或从微信读书书架添加公众号，勾选要采集的账号。
3. 选择 **全部历史推文** 或 **指定日期**，点击抓取按钮。日期包含起止两天，按北京时间计算。
4. 完成后自动下载 ZIP；下载记录还可下载合并文字和文章目录。

下载请求有正常间隔；遇到验证会自动切到验证页面，完成后回来点 **继续上次任务**。采集期间保持采集台标签页打开，已取得的正文和配图会复用。

**打包下载已采集资料**使用当前缓存目录和正文；不足部分会列入缺失清单。视频消息只保留标题和可取得的原文链接，不下载视频文件。

### 原文链接

插件从文章页面提取真实地址，核对标题、公众号和定位参数，未取得地址时明确标记缺失。

旧插件缓存中存在错误链接时，选好公众号和日期，点击 **修复原文链接并重新打包**。这会联网补取缺失链接并生成新资料包，保留已下载正文。旧下载记录不会自动变化，请使用新生成的包。

### 资料包

- `all-text.md`：合并文字、标题、日期与原文链接，含视频和正文缺失条目的说明。
- `all-articles.md`、`articles/`：带配图引用的 Markdown，以及逐篇 Markdown / HTML。
- `assets/`、`asset-index.json`：成功下载的配图及来源。
- `index.json`、`manifest.json`、`说明.txt`：目录、链接状态、覆盖范围和缺失项。

`archive_complete` 表示本次目录内的正文、链接、图片是否齐全；`collection_coverage_confirmed` 仅指所选范围的微信读书目录覆盖，不证明公众号历史完全收录。原文链接经过元数据核对，未逐条访问微信公开页，仍可能受删除或访问限制影响。

## 使用两个 Skill

将完整 Skill ZIP 交给支持文件和代码执行的 AI，或将相应源目录安装到所用工具的 Skill 目录。生成器在 AI 的执行环境内运行：原生排版生成器使用 Python 标准库，Word 加粗审核需要 `python-docx`；周报脚本需要 BeautifulSoup。各 Skill 的依赖见对应 `requirements.txt`，在 AI 执行环境中用 `python -m pip install -r requirements.txt` 安装。

两个 Skill **以 `xiumi-bridge/v4`、`mode=native-layout` 和必需字段判断兼容性**。Skill ZIP 供 AI 使用；插件导入的是 AI 生成的 `.xiumi.json` 文件。

### 按已有模板排版

在秀米打开源稿件，用插件 **抓取并下载 .xiumi.json**。把抓取包、文案和配图交给原生排版 Skill，生成新的 `.xiumi.json`。在秀米打开另一份空白图文，用同一个插件选择文件并 **导入**。

### Hello Week 周报

将采集资料包、期次与时间范围交给 Hello Week Skill。Skill 自带模板、固定素材和生成器，完成资料筛选、文案与原生排版后输出 `.xiumi.json`，用插件导入秀米。

周报默认在“详情请见”中为原标题插入超链接，直接使用采集到的真实原文地址。缺失地址时保留纯文字并提示；需要关闭时设置 `links_enabled:false`。

发布副本使用示例邮箱 `weekly@example.com`；生成前按实际需要提供 `contact`、`submission` 与 `credits`。模板中的学校、栏目及示例内容需按使用场景核对。

新建空白图文导入后插件会尝试保存；如提示保存失败，请先在秀米手动保存再关闭。

## 本机数据与权限

订阅、正文、图片和下载记录保存在扩展本机 IndexedDB；最近一次秀米导入包保存在扩展本机存储。

- `activeTab`、`scripting` 和站点权限用于秀米操作及微信读书页面请求。
- `storage`、`unlimitedStorage` 用于导入包缓存和采集资料。
- `cookies` 用于用户主动退出微信读书，会同时影响当前浏览器内的微信读书网页。

本项目不上传微信登录信息到第三方服务。插件和 Skill 的第三方许可分别保留在对应目录内。

## 后记

README 除后记以外全是 AI 写的，不过前面的部分我删了不少 GPT 经典的防御性和此地无银三百两的表述。

总之，在鸽了足足两个月之后，我终于又想起来更新 github 了。

好吧其实是因为大例会快到了，再不完善一下到时候没东西可讲了（

这段时间里，我想通了，agent 似乎没有那么必要啊，感觉不如免费的网页端。事实上，一个好的 skill 就足以解决大多数排版问题了，这就是模型发展带来的福报啊。我们唯一需要做的，就是这么一个插件，用它来抓取模板，然后发给 GPT 修改、排版，最后再通过它导入回去。

暂时不考虑让 AI 自主设计，我觉得至少当前来看全新的排版还是需要人工进行的，我做这个东西的初衷也只是自动化那些有明确模板的推送，例如新生杯等每年都会有的活动，或者其他需要与第一篇保持相同风格的推送。

现在的插件得到了大更新，终于不再是基于 HTML，而是真正做到了使用秀米能识别和接受的原生组件，这为后续的人工修改提供了极大的便利。后续，我打算继续研究如何让 GPT 能够使用上传的模板以外的组件，也就是增加模板库的容量，并增强它自我审核的能力，争取在照搬已有模板的基础上，让 AI 能够加入自己的创造。

关于 hello week，其实在自动化上遇到过一些些困难。一是 RSS 爬取公众号文章的方法失效，和 GPT 研究了半天找到了这个使用微信读书的方法；二是微信读书又不知道怎么了，爬取到的公众号链接突然出了问题，导致每次原文链接都需要我自己插入，现在也已修复了；三是我自己闲着没事做，加了一个下周百讲演出速览的环节，这玩意我是真看不到爬取它的希望，只能每次手动添加。这样综合下来，制作一篇 hello week，大概需要 20-30min，应该说还是可接受的。

好像也没有什么好说的了，总之就是一个很简单的小工具吧，本质上还是 AI 太好用了。

关于校会推出的那个智慧排版台，我认为很有想法，做好了是有希望可以完全替代排版的部门的，可惜看起来想做好并没有那么轻松。不过它确实给了我一点启发，后续也许会做一些类似的功能，也可能不会。
