# Hello Week 固定版式与文本排版审核

## 1. 本 Skill 与通用排版 Skill 的边界

Hello Week 是固定视觉体系的周报。原生组件库允许**按当期资讯数量**复制、删减和重组资讯条目，但不需要每期自由设计栏目骨架：开场 → 投稿 → 上周回顾（有内容才出现）→ 下周及后续（有内容才出现）→ 固定百讲空白框 → 重要提示（按需）→ 联系方式 → 代码式结尾与署名。每期以实际新闻决定分类、标题和内容，不按来源抓取稿的历史条目机械替换。

原生蓝色分类条、蓝底标题、浅蓝正文面板、勾选信息字段、代码样式和固定装饰保持稳定。首先遵守栏目功能和原生视觉，只有实际显示风险才局部调整其尺寸与约束。

## 2. 正文默认不缩进（包括长正文）

- Hello Week 的时间、地点、报名资格等字段本身有蓝色勾选符；动态资讯的叙述通常置于紧凑的浅蓝色信息区，**默认使用无首行缩进的自然段**。文字很多并不意味着自动加 `text-indent`。
- 可以通过拆分语义段落、保持正常段距、优化信息字段顺序来改善阅读。不要因为正文超过 70 字、100 字或任意阈值就给每段添加 `2em`。
- 极少数特殊稿件包含独立、连贯的多段叙事，且缩进符合该区域的视觉设计时，AI 可以在确认必要性后针对**单条资讯的正文**显式指定 `typography: {"first_line_indent":"2em"}`。不得给标题、勾选字段、联系栏、百讲空白文本框或其他固定栏目批量加缩进。
- 秀米的原生缩进存于段落 HTML：`<p style="text-indent: 2em;">…</p>`，不使用外层 `txt1.style.textIndent`。如果原模板已经用其他方式区分段落，优先保留原有做法。
- 默认省略 `typography.first_line_indent` 或设为 `"none"`。历史数据若包含 `"auto"`，生成器会按**不缩进**处理，避免旧版自动判断再次影响输出。

## 3. 西文打断仅按需要开启

- 正常中文和短英文句子保留原生自动换行。只有确实存在很长的 URL、英文标识符、连续字符，且使特定文本区的折行异常时，才显式设置 `typography: {"western_break":true}`。
- 原生设置对应 `txtN.constraint.wordBreakMode="breakAll"` 和相关段落 `word-break: break-all;`，只作用于该条资讯的正文组件，不改变模板其他模块。
- 默认关闭。若用户数据显式使用 `"auto"`，生成器仅对长连续西文按启发式启动；此结果仍要检查实际阅读效果。

## 4. 标题、居中和其他问题

- 分类与资讯标题保留原有配色、间距和原生容器，只在标题确实可能溢出时处理 `flex`、宽高或换行，不靠压缩原文事实解决。
- Hello Week 的动态资讯正文通常保持左对齐或两端对齐；不因文本出现在彩色框内就把整段居中。只有短题签或固定的短引导句确实需要居中时才用居中，并在长度较大时按语义断行。
- 检查二维码/动图的占位、分类与资讯条目成组、段距、标题是否换行以及相邻模块衔接。**百讲演出必须保留原生方框和唯一空白文本组件，不为它加缩进或内容。**
- 静态 JSON 审核可以提示风险，不能取代真实秀米手机端预览；发现问题后只修改受影响的原生实例，避免破坏固定视觉体系。

## 5. 生成器的可选数据字段

`body` 可配置（可完全省略）`typography`：

```json
{
  "title": "本期资讯标题",
  "body": ["第一段内容", "第二段内容"],
  "typography": {
    "first_line_indent": "none",
    "western_break": false
  }
}
```

多数条目不需要写 `typography`，上述设置即为默认效果。特殊情况下才明确改为 `"2em"` 或 `true`；不给其他条目带来连锁影响。`western_break:"auto"` 属于显式启发式选项；`first_line_indent:"auto"` 为旧输入兼容，效果等于 `"none"`。
