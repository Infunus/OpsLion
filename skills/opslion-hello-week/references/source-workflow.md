# 资料读取、期次与跨来源事件工作流

由旧版 Hello Week 文案 Skill 的完整资料处理规则整理，产出接口已改成原生 `weekly-content.json`。

## 1. 识别素材包

优先识别 `all-articles.md`（候选文章全文）、`index.json`（文章 ID、公众号、题目、原文 URL、发文时间）、`manifest.json`（采集范围、失败记录），存在 `asset-index.json` 时用其映射图片所在文章和原始 URL。ZIP 的文件名和字段可能变化，先实际浏览结构，不机械要求旧字段。文档、海报、截图中关键资格/时间信息同样需要读取。每篇文章末尾可能有改期、附件和补充，不能只读开头。

建立**内部采编表**，每条候选事件至少包括：`event_key / 原文章ID+位置 / 事件主体 / 发生与报名节点 / 对象与资格 / 相关性证据 / 真实来源URL / 最新有效状态 / 判定（选入、合并、排除、暂缓）`。表格仅供内部核对，正文不输出这些列。来源无法确定时记录不确定性，不能猜补。

### 来源覆盖

来源文章可能跨近三周；只对实际收到的材料声称覆盖。用户只提供七天素材不能称“已查遍近三周”。若用户要求自行补充检索才补充，并标识新增来源。校会和其他学院可以作为候选来源，但**收录严格遵循本期回顾/预览不同相关性规则**，不能按公众号一票通过。

## 2. 期次日期计算

如用户提供已确认的本周七天范围 `S...E`，通常按北京时区 `Asia/Shanghai` 处理：回顾 `S...E`，预览 `E+1...E+7`（包含端点），供参考文章检索的三周范围 `S−14...E`。用户明确指定的回顾和预览日期优先，不能擅自改范围；学期周次不能由模板样例推断。

需要确定**期次快照**（可优先采用回顾结束日或用户给出的编辑时间），用于判断报名是否已经截止。历史期次不能拿当前系统时间直接替代。缺少必要日期边界时，先从已确认素材中确定；无法确定时在交付外说明时间筛选不完备，不能虚构某期。

## 3. 判定“事件”而不是“推文”

- 一篇合集可以有零个、一个或多个独立事件。联合讲座与分会场若是同一事件的不同环节可合并；不同届次、独立报名的独立报告要拆开
- 事件时间可以是**举行、明确开放期、报名/材料截止、领奖、名单/结果正式发布、执行或变更生效日期**。多个日期各有意义，必须标清
- 事件本身不在范围内，但本期有重要有效截止：可因截止入选，同时保留远期举办日。未见明确持续期间不能把“某月举办”推断为该整月都有效
- “近期”“敬请期待”“下个月左右”等缺乏可落地日期时不硬填具体时段。相对时间需可靠发文日和上下文换算，日期与星期冲突时查更正，否则暂缓有关安排
- 已过举办日期的预告**不等于**活动确实举办；没有回顾来源时用“计划于”之类中性措辞，不杜撰已举行的结果
- 所有有效事件日期及节点均不在期次关注范围的，不能因文章刚发布就收录；只有真正会持续影响本期信科本科生的有效通知可按其实际效期判断

## 4. 变更、取消和多篇合并

先识别**明确更新与取消**，再根据最后一个有证据支持的有效安排筛选。后发的纯转发不能自行覆盖举办单位原通知。关键时间/地点/资格若冲突且无更正，暂缓；非关键字段争议可省略。

比对事件正式名称、届次、主题、日期、报告人、主办方、互引关系和报名要求，合并同一事件的报名/提醒/回顾/多个公众号重复推文；保留对最新事实有实质贡献的来源，单纯重复不再多写一条。只是题目相似或同一主讲人不构成相同事件。若仍有预览期有效节点，一般只在预览写一次；只剩回顾期节点则放回顾。

## 5. 内容筛选的相关性证据

**回顾：** 需要指向信科本科生的明确关联：本院、本科生面向对象、本院学生活动、本科生获奖或参与等。校学生会、计算机学院、集成电路学院来源本身不足以证明关联。研究主题像 AI、芯片、计算机也不足以证明本院本科生关联。

**预览：** 需要信科本科生实际可参与或事项直接相关：检查本科生、专业、年级、院系、研究生专属、报名入口与截止、费用或资格。校级全体本科生开放事项通常合格，外院组织的本科生开放活动也可合格。面向研究生、教职员工或限制其他院系的内容不得混入。

## 6. 来源和图片

原文题名要保留完整；保存采集资料包提供的 HTTP(S) 原文 URL 和来源证据。默认**成稿插入可点击超链接**，在“详情请见：原文完整标题”中给标题链接到该篇采集结果的真实原文地址，不加下划线。`link.url` 直接取 `index.json` 的 `url` 或 Markdown 中该篇的原文链接，保留参数；不要替换成微信读书阅读页或拼接猜测地址。地址缺失时保留纯文字并提示缺失。只有明确要求关闭时才设 `links_enabled:false`。不要把原文发文时间、公众号名塞进正文。仅有二维码时可写“入口见原推文”，不能根据图片臆造 URL。

关键资格或时间只在难以读清的海报里时，要进一步查看图片或暂缓该事件。图片源 URL 不可用时，非关键配图可以省略；原生模板固定图片另按组件规范处理。**百讲演出留给用户，不尝试抓取填充。**
