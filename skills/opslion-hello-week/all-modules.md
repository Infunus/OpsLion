# 组件全集：结构样例与生成机制

可运行的完整示例在 `examples/06-all-modules.json`；它覆盖全部 14 类原生种子（其中部分为自动插入）。执行：

```bash
python scripts/build.py examples/06-all-modules.json -o 全部组件测试.xiumi.json
```

**所有内容都是占位样例，不可发布。** 生成的 `.xiumi.json` 是真正的原生秀米组件，不是静态预览 HTML。

## 自动出现、无需手写的组件

`banner → code_intro → divider` 固定开场；`shows_panel` 为正文末的必备空白百讲演出区；`code_outro → credits → footer` 固定结尾。中间视内容加入 `divider`、`section`、`transition_review`、`transition_notice`。这些结构已经在 `scripts/build.py` 定义了准确顺序。

## 人工最常填写的四组数据

**投稿模块**：`"submission":{"enabled":true}`，启用或省略完整原生组合。来源二维码及奖励声明需要确认。

**上周/后续资讯**：

```json
"review":[
 {"name":"学术信息","items":[
  {"title":"标题A","fields":[{"label":"时间","value":"已核对的时间"}]},
  {"title":"标题B","body":"已经核对的文字内容"}
 ]},
 {"name":"活动信息","items":[{"title":"标题C","fields":[{"label":"地点","value":"已核对的地点"}]}]}
]
```

`upcoming` 结构相同。每个大区一个原生 `news_panel`；其内部复制多个类别、标题和正文子组件。`fields` 顺序即正文输出顺序。`link` 可以附加 `"link":{"label":"原文标题","url":"https://..."}`，默认使用采集到的真实原文地址生成可点击链接；`links_enabled:false` 时仅显示文字。地址缺失时不猜测或拼接。

**百讲演出（必备）**：不需要数据字段。无条件保留“下周百讲演出速览”及其原生浅蓝方框，方框内恰好一个空白的原生文本框。放在后续资讯之后、重要提示之前，由用户在秀米中手动完成，不要自动填演出内容。

**重要提示**：`"notices":[{"title":"提醒标题","fields":[{"label":"截止时间","value":"具体时间"}]}]`。没有则不输出提示过渡和提示分区。

## 不要引入未经实现的字段

当前 `build.py` 没有提供独立的 `welcome`、`closing`、任意 `spacer`、自定义 `code` 数据模块；它们属于旧版 v1 的 HTML 模板概念。若未来希望把它们加入新模板，应该先取得**真实秀米原生组件**并扩展生成器后再更新文档，不能假装随便写一个 JSON 字段就会生效。

## 核验重点

- 新文字是否超出标题条或父级容器，必要时仅修改受影响的 `flex`、宽高或换行约束
- 资讯与分类是否按意图重复，是否存在空分类或历史占位文本
- 投稿 QR 是否为当期入口；百讲方框是否存在、位置正确、内部仅有空白文本框
- 结构预览只能核对顺序；真实视觉需在秀米导入后确认


**每期文案筛选规则：** 上周回顾仅选有明确证据与信科本科生直接相关的已发生事项；下周及后续选信科本科生可参与或直接相关的未来事项。回顾不保留报名人数等无用招募统计。每个动态资讯段落末尾不写句号；见 `TEMPLATE_CONTRACT.md` 第 3 节。
