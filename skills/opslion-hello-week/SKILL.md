# OpsLion Hello Week — 采编与秀米原生排版一体化 Skill

版本 **4.0.1**。**本 ZIP 自带原生模板、采编规则、生成器、示例与测试；不需要另附 Hello Week 模板 ZIP。**

## 兼容性判断

以文件中的 `schema: xiumi-bridge/v4`、`mode: native-layout` 及 `nativeLayout.blueprint`、`nativeLayout.sequence` 等必需字段判断兼容性，不检查或要求浏览器插件的具体版本号。结构缺失时说明缺失字段；仅版本号不同不构成拒绝处理或要求升级的理由。

## 任务和最终交付

读取用户提供的当期素材，完成 **逐篇读原文 → 拆分独立事件 → 确定日期和受众 → 排除/合并/更新 → 撰写资讯 → 映射真实原生组件 → 出包审稿**。默认仅交付一份本期 `.xiumi.json`，如有关键材料缺失、冲突或需要用户完成的固定栏目，在成稿之外简短说明。

最终导入文件是 `xiumi-bridge/v4` + `native-layout`，供 **支持 xiumi-bridge/v4 原生协议的 OpsLion 插件** 打开空白秀米图文一键导入并自动保存。**不输出旧版 `hello-week/v1` 的 `:::news` Markdown，亦不使用旧 HTML 排版器或重复制作仿秀米 DOM。**

采编记录不进入推文正文；必要时交付独立来源表，但不要在正文写数据源 ID、公众号发布日期等内部元数据。

## 开始前必读

1. `TEMPLATE_CONTRACT.md` — 当前文案、筛选和原生结构的优先规则
2. `references/source-workflow.md` — 资料包读取、时间归档、去重、更新与证据
3. `references/writing-style.md` — 事件文案、字段选择、标点与参与条件
4. `component-guide.md` — **14 类真实原生组件**的用途和固定/可选规则
5. `starter.json` 及一份相近的 `examples/*.json` — 本期 JSON 内容结构
6. 有特殊结构或视觉风险时再看 `references/typography-and-layout.md` 和 `all-modules.md`

用户当期明确给出的范围、固定文案和栏目要求优先于示例。如果材料的来源字段不同于示例，按实际文件结构读取，不能为了满足某个虚构格式而丢掉内容。

## A. 资料读取和采编

- 用户给了素材 ZIP 时先检查完整内容：通常 `all-articles.md` 逐篇正文，`index.json` 文章原始标题/URL/公众号/发布时间，`manifest.json` 覆盖与缺失，必要时 `asset-index.json` 和海报图片。**一篇可能拆成多条事件，多个推文也可能指同一事件。** 资料结构不一致时以实际存在的文件为准
- 资料按事件抽取并保存内部出处：文章 ID / 原文标题 / URL / 具体段落 / 关键事实 / 时间与受众 / 采集完整度 / 状态（入选、合并、排除、暂缓）；不可将没有读完的资料写成“已全面核对”
- 对活动举办、报名/材料提交截止、阶段安排、取消/改期等分别记录**真实事件日期**。公众号发文日期仅作证据和相对时间计算，**不能直接当作活动举行日**；既有改期以证据明确的最新有效安排为准
- 先跨文章、跨来源去重再归栏。不同届次/场次/主题不可误合并；同一事件的报名、提醒与回顾如有共同事件身份则整合为一条，实际的后续行动节点决定是否进入预览
- 本期需要的日期、时间范围优先沿用用户给出的；没有期次信息时可依据已知日期命名，**不能猜学期周次**。日期筛选细则及特殊情形见 `references/source-workflow.md`
- 来源有缺失、时间或参加资格有关键冲突时暂缓对应事项，并在成稿外说明；可用其他可靠事实支撑的资讯继续制作

## B. 两个主分区的不同门槛（高优先级）

**上周回顾 `review`：只收与北京大学信息科学技术学院本科生直接相关的已发生事项。**

信科本院活动、信科本科生参与/获奖、本院本科生受影响的通知等可收。**校学生会、计算机学院、集成电路学院的历史活动，不能仅因同属北大或研究方向相近便进入回顾**；只有原文明确表明与信科本科生有联系时才可收。

**下周及后续 `upcoming`：只要信科本科生可以参与或事项明确与其相关，就可收录，不受公众号发布渠道限制。** 大信科、北大校会、其他院系、校级及符合条件的其他组织均可作为来源；研究生专属且本科生不具资格的事项不收。对报名资格、截止时间、活动尚有效等必须查证。

回顾与预览都要满足本期时间或有效行动节点条件，不因“最近发布”自动入选。同一事件原则上只出现一次；有尚未结束的有效后续安排时通常放预览。

## C. 文案规则

- **每条动态资讯的段落末尾、信息字段末尾不加 `。`**；段落内部可使用句号。专名、原文正式标题、问号和引号等保持准确
- 回顾侧重“发生了什么、与信科本科生有什么关系、有什么内容或结果”。**已结束活动不写报名人数/报名热度/已失效报名方式**；确有新闻价值的获奖、成果、实际活动内容可以保留
- 常见字段为 **时间、地点、内容、详情请见**；讲座有依据可加报告人/主持人，通知按实际需要加报名截止、参加对象、材料提交等。缺失字段**整项省略**，不写“待定/未知”凑数
- 先把事件写成连贯的内容介绍，再将需要快速查阅的时间/地点/行动节点单列；避免把“获奖情况/信科参与/多项环节”碎片化成十几个无谓字段。不同场次、会场或真正独立截止可以分开列清
- 标题点出正式名称/届次/主题。保持事实准确，不为视觉适配而大幅删改、调整叙事或虚构结果；可去重复宣传语、合理分段、调整图的位置或少量措辞
- 默认 `links_enabled: true`（省略该字段时同样开启）：在 **“详情请见：原推文完整标题”** 中给原标题加可点击超链接，不加下划线。`link.label` 使用完整原文标题，`link.url` 直接使用采集资料包中该篇文章的真实原文地址（如 `index.json` 的 `url` 或 Markdown 中的原文链接），保留地址参数；不要使用微信读书阅读页，也不要猜测或拼接 URL。缺失地址时保留标题纯文字并提示缺失。只有用户明确要求不加链接时才设为 `false`
- 不在公开文案展示公众号、原文推送日期、抓取时间、内部证据编号；文案自足，避免“某篇推文介绍……”口吻

详见 `references/writing-style.md`；审查边界情形见 `references/editorial-review.md`。

## D. 原生模板：固定栏目骨架，可变资讯内容

本包的 `hello-week.template.json` 提供 14 类真实秀米原生组件。**Hello Week 有固定栏目骨架**：开场 → 投稿 → 上周回顾（有内容才显示）→ 下周及后续（有内容才显示）→ 必备的百讲演出空白框 → 重要提示（按需）→ 联系方式 → 代码结尾与署名。资讯条数、分类、字段和正文长短由本期事实决定，可在对应区域复制、增减和编排子组件。不得把来源文章中原有资讯的先后和篇幅机械照搬，也不得为了迁就组件大幅改动本期文案。

`review`、`upcoming` 是任意数量的 `{name, items}` 分类；每个 item 可有 `title`、有序 `fields`、自由 `body`、来源 `link` 等字段。**空分类和空分区省略**。`notices`（重要提示）仅当本期有实际提醒内容时生成。默认保留栏目动图、代码开头结尾、投稿区、联系区和署名区；投稿二维码/联系方式是否继续有效须核实。

### 百讲演出：唯一强制留空的内容栏

每期**无条件保留**“下周百讲演出速览”原生标题和原生浅蓝方框，固定排在下周资讯之后、重要提示之前。框内 **恰好一个空白秀米原生文本组件 `<p><br></p>`**；不得加入往期海报、节目表、内容提示、链接或预设文字。**由用户导入后手工完成**，不从素材库爬取这一栏。没有其他资讯也不得删掉该框。

### 字体与审核

保留源稿原有的蓝色渐变分类、蓝底标题、勾选字段、代码视觉和图片。**Hello Week 正文默认不加首行缩进，长文也不因字数达到阈值而自动缩进**：浅蓝资讯框、标题条、勾选信息字段已有清楚的视觉层次。仅当某个特殊段落确实需要独立的连续叙事排法，且实际效果适合时，才明确为该条目开启原生段首缩进。西文打断同样不默认开启，只有长英文连续字符影响折行时才使用。长标题先检查容器伸缩与折行；适合居中的短句可居中，长居中文字按语义断行。详见 `references/typography-and-layout.md`。

## E. 本期成稿文件

1. 根据已确认事实创建 `weekly-content.json`（可复制 `starter.json` 后**删除占位数据**）：包含 `title`、`links_enabled`、`submission`、`review`、`upcoming`、`notices`、`contact`、`credits`
2. 先运行 `python scripts/audit_content.py weekly-content.json`，检查明显缺失、段尾句号、可能的重复、回顾报名统计和长西文；**它只提示，不能代替逐条事实审核**
3. 运行 `python scripts/build.py weekly-content.json -o HelloWeek_本期.xiumi.json`。脚本从原生种子克隆组件、设置 UUID、拼装分类和正文，默认用采集到的原文地址插入可点击链接，自动插入百讲空白框
4. 逐条对照来源确认相关性、时间、主讲人、参与资格、已失效报名话术、细节保留、来源题名等；检视生成的 v4 结构、模块数和文本风险
5. 如可进入秀米，导入另一份空白图文查看移动端，主动修正明显溢出/裁切/错位；**纯离线格式检查不能冒充真实渲染通过**。最终只交付可导入 `.xiumi.json`，其它材料作为必要时的补充说明

可运行 `python tests/test_template.py`、`python tests/test_browser_slots.py` 和 `python tests/test_editorial_workflow.py` 检查生成器兼容性。

## 特别禁止

- 不能把旧版 `:::news` Markdown、旧 HTML 模块或者 `hello-week/v1` 作为本期导入包
- 不能用推文发布日期冒充事件日期；不能重复报道同一事件，也不能把研究生专属活动当作本科生预览
- 不能为填满栏目而捏造或扩写事实；没有资料时不生成虚构资讯
- 不能因为缺少百讲演出资料就删掉必备框，也不能自动填内容
- 不能把模板示例中的旧活动日期、姓名、联系方式或奖项当作当期事实
