# 默认原文一字不改、允许排版微调与改动说明（v2.4.3）

## 原则

**默认原文一字不改。** 绝大多数推送应直接采用原文的字句与标点，原样保留事实、叙事、情绪、信息量、风格和侧重点。排版编辑可以决定如何展示，**不应默认承担文案润色工作**。小幅编辑可以是正常的排版判断，并非每次都需要刻意修改；关键是有可观察的理由、调整克制且说明清楚。

### 允许的合理小幅调整（无需每次事先征询）

- 有清楚证据、确实影响阅读或事实准确性的明显错字、病句、标点误用与笔误，可以做最小必要修正；原本只是风格差异、重复强调或口语习惯时保持原文。
- **排版孤字行**：例如一句需要居中的文案自动折行后，最后一行只剩一两个字，显得突兀。可以选择在恰当语义处插入换行，形成相对均衡的两行；也可以在不影响内容与风格的前提下，删去一两个冗余字或少量调整词语/标点。依据实际手机预览确定更好方案，不要求把所有字号、容器方案全部尝试一遍。
- 标题、口号、图注、窄卡片等可根据布局合理微调：优先手动断行、局部排版调整，删字或换词也可作为直接可选方案。修改范围应与实际视觉问题相称；不以“绝对无法排版”为前提。
- 在不损害原稿的前提下修补显然的笔误、不一致之处；事实性纠正必须基于已知原稿其他部分或可核实的证据。对存在多种可能的矛盾、姓名、时间、比分等重要事实，保留原句并标记待确认，不能猜。
- 原稿衔接明显存在逻辑断裂且影响理解时，可最小限度修补连接语；没有明显问题时不能主动添加转场、总结、口号或评价。

### 不允许的行为

- 擅自大段重写、概括、移除关键事件、人物高光、细节、情绪、祝福、引语、观点或总结；哪怕改后“表意相近”也不可以。
- 为了制造修改而作同义词替换、全篇标点美化或「更像新闻稿」式润色；但为解决局部排版问题可有依据地调整少量字词、标点。
- 篡改姓名、学校、对手、比赛时间、比分、球员数据、事实因果等；有疑问而无依据时不自行补充或纠正。
- 由于版式不适配就删去长段：首先选择合适的原生正文/表格/滚动组件并修改容器宽度或段落分组。
- 将原稿中关键的阵容图、比赛照片移到不相关部分；丢弃原模板的“大信科”尾图、LOGO、二维码、署名区等固定资产。

## 内容编辑工作流（必须执行）

1. 读完整原稿，按文档实际顺序建立段落、表格单元格、图片和图注台账；标出比赛关键叙事、人名、数据、主要描写及强调表达。
2. **先原样放入组件，再观察实际排版**。通常直接保留原文字句；对具体问题（特别是居中末尾孤字行）采用语义断行、适度改尺寸，或在不伤文意的前提下删一两个字/略换词语。无需机械追求每次都零改字，也不要为追求版面整齐牺牲作者风格和细节。
3. **纯手动换行**不算文字增删改，记录在排版说明即可；**删字、换词、改标点、增删句子**则每项在 `content-changes.json` 记录：`before`（改前完整文字单元，可空表示新增）、`after`（改后完整文字单元，可空表示删除）、`reason`（具体原因）、`kind`（punctuation/typo/wording/grammar/layout/add_sentence/delete_sentence/factual_correction/other）、`location`（原稿或成稿位置）、`reviewed: true`。连续长改动按自然段逐项记录；不能把大幅精简包装成一条“优化文案”。
4. 使用 `scripts/verify_source_fidelity.py` 生成差异报告，对每一条原文缺失/成稿新增进行解释并复核。修正工具发现的“未登记差异”或回滚不必要改动。工具本身只能做**文字差异检测与登记核对**，不能判定事实正确、编辑是否必要或写作风格是否受损，必须人工审稿。
5. 对编辑后的全文再通读一遍：人物的出场、成就、动作和情绪是否受到削弱？比分、数字、人名、时间是否出现更改？有无来自旧模板的过期内容？原稿图片顺序与品牌尾图是否正确？若出现严重问题，不得交付。
6. 交付导入包时附简明「文案改动说明」：按类别/位置说明改了哪里，为什么；**实际删句或添句要明确列出对应原句/新句**，较多标点改动可合并说明共性并留详单。若只有断行而字句不变，应写“未修改原文字句，仅调整换行”；若实际改动，按位置说明原文、成稿与排版/纠错原因。

## 自动差异与核对

```bash
python scripts/verify_source_fidelity.py \
  --source 文案.docx --packet article.xiumi.json --out draft-diff.json

# 自主审查 draft-diff.json 的 missing / unexpected，填写修改台账
python scripts/verify_source_fidelity.py \
  --source 文案.docx --packet article.xiumi.json \
  --changes content-changes.json --out content-review.json \
  --markdown-report 文案改动说明.md
```

变更台账例子（两条）：

```json
{
  "changes": [
    {
      "location": "首发名单后介绍段",
      "kind": "typo",
      "before": "队长羊瑞整守中场。",
      "after": "队长羊瑞镇守中场。",
      "reason": "改正明显错别字",
      "reviewed": true
    },
    {
      "location": "上半场比分说明",
      "kind": "punctuation",
      "before": "半场结束 信科2:1城环",
      "after": "半场结束，信科 2:1 城环",
      "reason": "修正标点和空格，提高阅读流畅度",
      "reviewed": true
    }
  ]
}
```

不填写 `--changes` 时，工具只发现差异；纯空白/换行变化会被归一化为无文字差异。删改一两个字会产生文字差异，需登记位置、原文、成稿和具体排版原因；有未登记差异时 `ok=false`。提供的台账须逐项对应真实差异，缺登记、无原因、未审核均不能交付。完整登记可以使机械检查通过，但**人工仍要审核修改是否合理、内容是否完整**。某个段落被大量删去，即使登记了，也应先考虑改布局或恢复原句。

源文件若有文本框、图片内文字、嵌套表格、页眉等解析不完整的内容，另外做人工检查，不得宣称程序涵盖了这些对象。内容检查、原生结构检查、本地视觉预览和秀米真实渲染是四层不同的验证。
