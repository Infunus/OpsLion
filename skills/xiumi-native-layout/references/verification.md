# 测试层级与交付措辞

## 此 Skill 能直接证明的内容

1. 文件结构：`native_packet.py validate --images` 检查 v4 模块、槽位、索引、文字、内嵌图片 Base64 与格式，避免无效引用。
2. 本地代码链路：`build` 确认能基于真实 blueprint 生成 v4 包；使用 `stylePatches` 可以针对单实例复制原生模块、同步迁移 slot IDs。
3. 静态风险识别：`audit` 报告固定高宽、不可伸缩 flex、长文增长等。它只是一份候选列表，不能证明真实页面中一定发生溢出，也不能证明没有警告就一定不溢出。
4. 内容审核：模型对照文稿全文、真实素材画面和交付成品实际文本判断准确性与改动幅度；标题/段落顺序和叙事逻辑应保留。这一步不能被 schema 校验替代。
5. 组件语义审稿：核对标题、正文、分割线和图框的用途，检查居中长句断行、段首缩进是否适合实际组件与文本层次（包括不缩进更好的情况），以及连续长西文是否需要“西文打断”；静态工具不能独立判定全部视觉效果。

## 需要另外获得实际证据的内容

6. 秀米页面渲染：在真实秀米编辑器或与之等价的可信渲染环境截图，检查文字容器是否正确自适应、图片裁切是否合适；从此时起才可说“已检查实际渲染”。
7. 秀米服务器保存：插件在登录账号下导入并成功获得稿件 ID，及保存重开后的表现；仅插件模拟测试不等于服务器验证。
8. 微信端展示/发布：需真实预览或实际微信环境，不能被本 Skill 预先证明。

程序既不登录用户秀米账号，也不访问私有云保存接口。没有浏览器实际证据时，交付可用的 `.xiumi.json` 并明确“完成本地结构和静态排版审核，尚未在秀米编辑器实渲染验证”。

## 发布前一般确认

- 没有残留上一期的日期、名称、数值和图片
- 无缺失段落、错误重复、空白图框或编辑说明
- 新文字的强调/超链接边界正确
- 成稿不是照搬旧稿的组件顺序；原稿主要段落及图片对应关系仍被保留
- 正文、标题、分隔元素用途合理；居中的长句适当语义断行，段首缩进以实际效果为准而非长度阈值（包括保留无缩进），长英文文本按需检查西文打断
- 装饰图、背景、Logo、二维码仍保留正确位置
- 原生布局修复集中于问题容器，其他颜色/字号/模块不漂移
- 成稿使用 `.xiumi.json` 的 v4 原生格式，与抓取包是同一种协议

不要为了做质量检查再给插件加入哈希、二次确认弹窗、原位更新或模板编辑页面。
