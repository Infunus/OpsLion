# 通用原生排版审核：发现风险、定位根因、最小修复

本规范独立于具体用户、文章题材和历史故障案例。每份秀米模板的组件树、约束与内容不同；**先看这份稿件中的实际证据，再决定修改什么**。

审核顺序先查 **内容忠实度、组件语义匹配、段落组织**，再查局部 CSS 属性。原模板原有排列顺序不应凌驾于本期文案。对应细则见 `composition.md` 与 `typography.md`。

## 1. 从全稿识别潜在风险（广度优先）

先逐段核对新文案、插图和实际组件的对应关系，再运行 `native_packet.py audit` 获取候选位置。人工继续检查下列类别：

| 现象或风险 | 典型成因 | 优先获取的证据 |
|---|---|---|
| 文字被裁切、出现内层滚动条 | 父级固定宽高、`overflow`、固定行高、换行限制 | 新旧文字长度、文本节点、全部祖先布局属性、可视截图 |
| 文字挤压图形或邻接模块 | 横向布局约束、绝对定位、不可伸缩子元素 | 受影响一行的所有兄弟组件及各自边界 |
| 内容重叠、遮挡、层级异常 | 定位、变换、负边距、`zIndex`、容器高度 | 层级树、实际重叠区域、手机宽度预览 |
| 图片拉伸、裁切、消失 | 图片实际尺寸/比例、容器比例、适配模式、上传地址 | 原图与导入图片、源样式和渲染截图 |
| 段间间距突变或整体错位 | padding/margin、模块被复制/删除后边界变化 | 前后模块接缝、重复实例、父容器高度 |
| 强调和链接作用范围错误 | 文字片段替换与富文本节点不对应 | 片段运行序号、原 HTML 结构、显示文本 |
| 旧文案或素材残留 | 模板复用时映射不完整 | 来源稿与新文案逐项比对 |
| 标题/正文/分割线混用 | 按旧顺序替换，没有识别组件语义 | 文案大纲与组件用途清单 |
| 为迁就模板大幅删改文案 | 槽位长度/数量被误当内容约束 | 原稿与成稿逐段对照、内容变更清单 |
| 居中长句拥挤/缩进导致错位/段落层次不清 | 对齐、断行、段距或缩进不符合段落用途 | 文案逻辑、视觉行宽、相邻组件与 `<p>` 的原生段落样式 |
| 长英文、URL 撑破窄容器 | 连续西文字符缺乏可用换行点 | 原生 `wordBreakMode`、段落 `word-break`、手机端视觉结果 |
| 不同视口布局不一致 | 固定尺寸、百分比与 flex 组合、文本折行 | 至少检查常见手机正文宽度与更窄宽度 |

没有任何一条静态启发式能保证发现全部问题。`constrained-text`、`grow-in-flex` 等提示只意味着值得检查，**不能当成已经确认发生裁切**。固定尺寸的图片、装饰和定位元素通常可能有意为之。

## 2. 从现象向组件树追溯（深度优先）

1. 先确定当前 `sequence` 实例，确定实际 `source` 和受影响的 `slot.id`。
2. 查受影响节点的 `text` / `src`、自身 `style` 与 `pose` 等现有属性。
3. 沿 `slot.path` 上溯其父级、祖先 `colN`、`items`、`_comp.style` 与 `constraint`；再检查同一行/组的兄弟节点。
4. 对照新旧文字长度、图片长宽比和实际可视区域，区分**内容变化、容器约束、邻接组件、资源错误、平台渲染差异**。
5. 提出一个最可能的根因和可检验的最小改动，必要时比较两个候选方案；没有证据不要同时修改多种属性。

秀米界面的“自适应/自伸缩”等选项与模型字段的映射，需要从当前模板的原生数据或实站控件前后差异确认；不要假定 `0 1 auto`、`1 1 auto` 或某一具体属性在所有组件上意义相同。

## 3. 修复决策

- 优先修改**发生问题的当前实例中**直接造成约束的节点；对于同一来源的其他复用位置不应同步修改，使用工作计划 `stylePatches` 生成实例级变体。
- 需要适配文字时，先分析布局空间与折行、最小/最大尺寸、内外间距、溢出方式；只有确认固定高度是根因时才考虑释放高度。
- 图片应以实际图像比例和模板意图为依据，避免通过强制拉伸或替换无关图片解决布局问题。
- 保留视觉语言（字号、字体、配色、边框、装饰和必要留白），避免以压缩字体、删除正文、整体重绘等方式掩盖根因。
- 若现有组件语义不适合承载新内容，优先从同一模板选择适当模块或复制完整原生组件，避免构造未经验证的新组件类型。
- 每次修复都应记录假设；修改后出现副作用则撤销该改动，再定位。

## 4. 实际渲染核对（环境允许时执行）

- 以本次成稿包导入的页面为依据；先看全文，再放大检查风险位置，注意模块接缝和滚动区域。
- 对比常见手机正文宽度以及较窄宽度，检查文字完整、可读、没有遮挡或意外滚动条，图片比例正确，组件顺序与层级符合模板意图。
- 从可见异常定位元素 → 查原生结构 → 做局部改动 → 重新生成 → **再次查看同一位置和邻接区域**；只有验证后才能称为已修复。
- 没有真实秀米渲染访问权限时，可完成结构和内容审核，并明确标记未进行秀米实站视觉验收。浏览器模拟或静态 JSON 校验不能替代真实渲染。
- 用户反馈的真实截图优先于静态猜测；截图没有展示的内容不要据此下结论。

## 5. 发布前的内容审校

核对全文是否完整，标题、正文、图片、图注、时间、数字、链接、署名与本期素材一致；与原稿逐段比较改动幅度与叙事先后，**大量实质删改即使视觉完整也不算通过**；所有保留旧文字应有明确理由。图片是正文内容还是装饰，要结合语义辨别。不要因为字体或组件形态相近就把新内容填入错误槽位。

## 6. 审核结果记录（内部）

以简短结构记录：`位置 / 可见症状或静态风险 / 证据 / 原因假设 / 修复属性 / 复核结果 / 尚未验证项`。无需在插件里添加新按钮、哈希拦截或编辑器，也不要求用户审核详细技术表格。
